# WinSetup Lite

**面向 Windows 11 的软件迁移与开发环境恢复工具**

换电脑或重装系统时，可以用 WinSetup Lite 导出常用软件清单，在新电脑上检查并补装缺失项，同时配置并验证 Python 环境。**用户确认本批任务后，程序会在后台安装、处理可恢复的错误，并检查结果。** 对部分安装错误，本地 AI 会根据报错选择下一步，由程序自动执行。

## 使用场景

- **换机或重装。** 在旧电脑勾选常用软件并导出清单。新电脑导入后，只补装缺失项，并可在同一批任务中配置 Python 或 PyTorch 环境。
- **课程实验或小组协作。** 共享一份 Git、VS Code 等基础工具清单。成员可在各自电脑上检查缺失项，查看每项的安装结果。
- **开始新的 Python 项目。** 用自然语言描述任务，例如「读取 Excel 并绘图」。本地 AI 从项目支持的库中给出依赖方案，供用户确认后安装。

WinGet 本身支持软件清单导入导出和批量安装。WinSetup Lite 用 WinGet 执行软件安装，把软件状态检查、失败恢复和 Python 环境验证放在同一批任务中。例如，补装 Git 和 VS Code 的同时，可以创建 PyTorch 环境，并验证它能否用 GPU 计算。 [WinGet 文档](https://learn.microsoft.com/windows/package-manager/winget/)

## 全自动安装如何运行

1. **确认本次任务。** 导入或编辑软件清单，勾选需要的应用。打开 **全自动安装**，按需选择开发环境。如果选择 **AI 配置 Python 环境**，先生成并核对依赖方案，再点 **授权并开始**。本次授权覆盖选中项目的安装和程序提供的恢复操作。
2. **检查并安装。** 程序通过 WinGet 按精确的软件包 ID 检查本机状态。已经安装的项目直接跳过，确认缺失的项目才进入静默安装。
3. **判断失败后怎么做。** 软件源数据缺失、可识别的网络错误等已知情况按规则处理。其他符合恢复条件的错误，将软件名称和错误摘要发给本机 Ollama，由 Qwen3 返回一个可执行动作和理由。
4. **在本机自动执行。** 程序校验模型返回的动作，再在后台执行对应的操作。需要重试时，程序会先复查当前状态；软件仍然缺失才尝试安装。用户可以通过 **操作记录** 查看模型理由、恢复动作和最后结果。
5. **复查并记录。** 程序再次通过 WinGet 查询安装状态，确认已安装才记为成功。如果刷新失败、重试后仍失败，或模型选择停止，程序会记录该项结果。若原安装程序超时且可能仍在运行，本批次后续的软件会标记为尚未执行。

### AI 可以触发哪些操作

| AI 返回的动作 | 程序会自动做什么 |
| --- | --- |
| `retry` | 等待片刻，复查软件状态，仍缺失时重试一次。 |
| `refresh_source` | 调用 `winget source update --name winget`，刷新成功后复查状态并重试。 |
| `stop` | 停止对当前项的恢复尝试，保留错误信息供用户查看。 |

例如，**Git 第一次安装失败，错误没有匹配已有恢复规则**。如果 Qwen3 从日志中判断软件源可能需要更新，它可以返回下面的结果。

```json
{
  "action": "refresh_source",
  "reason": "错误信息提示软件源索引可能需要更新"
}
```

程序收到后会**实际刷新 WinGet 软件源、重试安装，再查询 Git 的安装状态**。从选择动作到复查结果，都在用户启动的这次自动安装任务内完成。

## Python 环境如何配置和验证

| 模式 | 配置方式 | 验证方式 |
| --- | --- | --- |
| **AI 配置 Python 环境** | Qwen3 根据用途从 20 种常用库中生成依赖方案。用户确认后，程序用启动 WinSetup Lite 的 Python 创建独立的 `venv`，再用环境里的 `pip` 安装依赖。 | 运行 `pip check` 检查依赖关系，并实际导入方案里的库。 |
| **PyTorch 环境** | 使用内置的 PyTorch 2.9.1 和配套版本。可选 CPU、必需 NVIDIA CUDA，或优先 CUDA 并允许回退到 CPU。 | 核对版本，在指定设备上实际执行一次张量运算。选择必需 CUDA 时，只有 GPU 运算通过才算完成。 |

遇到 `pip` 安装失败时，程序可以按网络错误规则重试，或由模型根据报错决定是否重试已确认的依赖方案。当前的软件清单保存软件名称和 WinGet ID，可跨电脑导入。Python 依赖和 GPU 要求在发起任务时单独选择。

## 下一阶段：让一份清单同时恢复软件和环境

把 Python 解释器要求、依赖版本、CPU 或 GPU 要求写进清单。用户可以指定必须保留的版本、允许调整的范围，以及能否回退到 CPU。新电脑导入后，程序按本机条件形成安装计划，并记录每项的验收结果和进度，以便中断后复查已完成项、继续处理剩余任务。

计划为模型增加几项可以调用的检查，包括识别本机 Python 解释器、查询 NVIDIA 驱动和检查候选依赖能否安装。模型根据每一步返回的结果选择下一项检查或候选配置，程序校验选择后执行。

例如清单要求 **PyTorch 2.9.1 和 NVIDIA GPU**，允许调整 CUDA 构建。如果 PyTorch 能导入但 GPU 运算失败，程序先检查显卡和驱动，让模型根据错误和检查结果选择兼容候选，再在独立环境中测试，并重复同一项 GPU 验证。所有调整都以清单确认的版本和设备要求为准。

## 测试与评估

当前代码通过 **32 项自动化测试**。其中，恢复流程测试模拟安装失败和模型返回的动作，检查是否触发了刷新、重试，以及是否拒绝程序支持范围之外的动作。

下一步会使用相同的 Windows 初始状态、迁移清单和验收项，对比固定规则和多步 AI 排错。记录通过的验收项、人工介入次数、恢复耗时，以及最后采用的方案是否满足清单要求。

## 快速开始

在 Windows 11 上准备可用的 WinGet 和带 Tkinter 的 Python 3.11 或更新版本。在项目目录打开 PowerShell，运行下面的命令。

```powershell
winget --version
python -m winsetup
```

在旧电脑用 **扫描本机软件 → 导出所选** 生成 JSON 清单。把清单带到新电脑，用 **导入清单 → 全自动安装 → 授权并开始** 执行。也可以在软件清单中手动搜索和添加应用。

使用本地 AI 时，先启动 Ollama，再下载默认模型。 [Ollama Windows 文档](https://docs.ollama.com/windows)

```powershell
ollama pull qwen3:1.7b
```

启用模型后，也可以在主界面输入电脑用途来生成软件推荐。核对推荐结果后，选中要添加的应用并加入清单。

运行测试。

```powershell
python -m unittest discover -s tests -v
```
